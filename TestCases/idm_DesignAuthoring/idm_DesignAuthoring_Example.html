2.2. Summary

Design Authoring involves using 3D software to create a Building Information Model (BIM) based on criteria important for translating the building's design. This process primarily utilizes design authoring tools for model creation and audit/analysis tools for studying or enriching the model's information. Design authoring tools are the initial step towards BIM, connecting the 3D model with a powerful database of properties, quantities, means and methods, costs, and schedules.
[Source] BIM Project Execution Planning Guide Version 2.2 Appendix B-12

Potential Value:

  • Transparency of design for all stakeholders
  • Improved control and quality control of design, cost, and schedule
  • Enabled powerful design visualization
  • Enabled true collaboration between project stakeholders and BIM users
  • Improved quality control and assurance

2.3. Aim and Scope

Aim:

The aim of this IDM specification is to establish standardized processes and information requirements for Design Authoring using BIM. This IDM defines how 3D design data is systematically authored, enriched, and delivered to facilitate downstream use in construction project management, coordination, and analysis. The goal is to support high-quality, transparent, and collaborative BIM-based design that serves as the foundation for all subsequent project stages.

Scope:

This IDM covers the use of 3D design authoring tools to create, structure, and maintain Building Information Models in accordance with project-specific BIM requirements. The scope includes:
  • Initial Model Creation: Crafting a digital representation of the building using BIM authoring software, encapsulating geometry as well as associated information such as materials, quantities, and spatial relationships.
  • Design Coordination and Revision: Facilitating information exchange to enable collaboration and transparency between clients, architects, engineers, and other stakeholders.
  • Quality Assurance: Implementing checks using model audit and analysis tools to ensure completeness, consistency, and accuracy of both geometric and non-geometric data.
  • Deliverables: Defining exchange requirements tailored to subsequent uses such as design review, cost estimation, scheduling, and construction planning.

2.6. Target Project Phases

ISO 29481 series use the ISO 22263, one of the simplest project lifecycle classification systems, as the standard to provide users with a common basis to search for, use, and repurpose existing IDMs. The target project phases of this IDM specification are listed below, mapped to those of the American Institute of Architects (AIA) and the Royal Institute of British Architects (RIBA). This document does not intend to specify information requirements beyond the production phase; therefore, the maintenance phase is not included. However, the design authoring task may be extended to the maintenance phase depending on the scope of a project.

2.7. Intended Users

  • Client
  • Designers (architects and engineers)
  • BIM managers and coordinators
  • Other project stakeholders require design information for review, coordination, and downstream use.

2.8. Value Proposition

Adhering to this IDM will:
  • Promote transparency and consistency in design communication among stakeholders.
  • Enhance quality control and cost/schedule management by providing reliable, well-structured model data.
  • Reduce errors, omissions, and rework during project delivery.

2.9. Required Resources & Competencies

The effective application of this IDM requires:
  • Proficient use of design authoring software (e.g., Autodesk Revit, Graphisoft Archicad, Bentley AECOsim, etc.).
  • The ability to manipulate, navigate, and review complex 3D models.
  • Fundamental knowledge of design and construction principles, including construction means and methods.

Figure 1. "Design Autoring" Process Map

Description: This process map illustrates a collaborative design process across three swim lanes representing different stakeholders: Client and Design Team. The process begins when the Client initiates a "Request Design" activity, which generates a Design Brief document that flows to the Design Team's "Generate Design" process. The Design Team creates a Design Submission Package that moves back to the Client for the "Review Design" activity. At this point, a decision gateway (marked with X) determines whether the design is approved or requires revision - if approved, the process ends at the terminal state, but if not approved, the Client performs a "Request Revision" activity that creates a Design Change Request document. This revision request triggers the Design Team's "Revise Design" process, which updates the Design Submission Package and sends it back to the Client for another review cycle. The diagram effectively shows the iterative nature of design development, with document exchanges facilitating communication between parties and feedback loops ensuring client satisfaction before final approval, while the middle Exchange Requirements lane serves as the repository for all project documentation throughout the process. The Design Brief, Design Submission Package, and Design Change Request—which are represented as Data Objects in the process map—correspond to the sub-ERs: er_DesignBrief, er_DesignSubmissionPackage, and er_DesignChangeRequest.

4.2. Sub-Exchange Requirements

4.2.1. Exchange requirement for a design brief (er_DesignBrief)

Decription: Design authoring is a complex process that typically involves multiple exchanges of information. In this example, however, the process is simplified to focus on only three key information sets: the design brief, the design submission package, and the design change request. The exchange requirement for design authoring, as illustrated here, is an aggregation of three sub-ERs—design brief, design submission package, and design change request. The following section details the specific information units required by each sub-ER, with particular emphasis on the design submission package.

Name Brief
Data Type Document
Is Mandatory true

4.2.2. Exchange requirement for a design submission package (er_DesignSubmissionPackage)

Description: A design submission package is a comprehensive collection of documents, drawings, and supporting materials that formally presents a design proposal to clients, regulatory authorities, or other stakeholders for review and approval.

Information Units for Design Submission Package:
